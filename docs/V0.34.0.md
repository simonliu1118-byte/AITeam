# V0.34.0

## AITeam 變成可攜資料夾

從 GitHub Release 下載 zip、解壓到任何資料夾，**那個資料夾就是 AITeam 的家**：專案清單、
從 GitHub 抓下來的 Repo、工作區、歷史紀錄都放在裡面。整個資料夾搬到別台電腦照樣能用。

以前只要電腦上有 `D:\AITeam` 就一定用它，等於綁死在 D 槽。

### 家怎麼決定

1. exe 旁邊已經有 `data` 資料夾 → 這裡就是家（可攜）。
2. 沒有，但這台電腦有舊的 `D:\AITeam` → 沿用它，既有的專案和紀錄才不會「不見」。
   想讓 `D:\AITeam` 也變成可攜的家，把新的 `AITeam.exe` 放進 `D:\AITeam` 就好。
3. 其他情況 → exe 所在的資料夾就是家，第一次開啟時會建好 `data`。

（舊的 `current` 子資料夾安裝方式、`AITEAM_ROOT` 環境變數照舊有效。）

### 搬家不會壞

專案清單裡，家裡面的路徑改存**相對位置**，搬家、換磁碟代號都對得上。舊版存的完整路徑會在
讀取時自動對應：原本的位置不在了，但新家裡找得到同一個 `repos\…`，就用新家的。

### 帶不走的東西

三家 AI CLI、Git、GitHub 的安裝與**登入**是跟著電腦走的，也不應該放進可攜資料夾
（隨身碟掉了等於帳號外洩）。新電腦要先裝好並登入一次；自動安裝與開瀏覽器登入排在下一版。

## 自動更新

跟 CYERPAutoInput 同一套做法：

- 開啟後 20 秒查一次 GitHub 上的正式 Release，之後每 4 小時查一次。只認 AITeam 自己的
  `vX.Y.Z`，草稿、預先發布、Actions 的測試包都不算。
- 有新版就在背景下載，**核對 SHA-256**，不符就不用。主視窗上方會出現提示列。
- 等 AITeam **閒著**（沒有任務在跑、沒有會議或其他視窗開著）才倒數 10 秒，可以按
  「稍後再更新」延 30 分鐘。有任務在跑就一直等；直接關掉 AITeam 時也會順便換上新版。
- 換檔時會出現「正在更新」的小視窗：先備份、再覆蓋，覆蓋失敗就還原，舊版照樣能開。
- 重新開啟後顯示「已更新到 Vx.y.z」，或「更新失敗」並說明原因，8 小時後再試。
- 只換程式本身，家裡的資料（data、repos、history……）不在更新包裡，不會被動到。

### 正式 Release 流程

`release-windows.yml`（手動觸發、只能從 main）補上共用規則要求的檢查：
`BUILD` 必須是 0，而且要有這一版的 `docs/VX.Y.Z.md`，Release 說明直接用它。

**注意：這一版本身需要手動觸發一次 Release，之後的版本才有地方可以自動更新。**
在這之前用的工程測試包（Actions artifact）不會被自動更新認得。
