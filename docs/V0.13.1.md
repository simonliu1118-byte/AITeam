# AITeam v0.13.1

跟這次的治理討論直接相關：**Change task 完成合併後，AITeam 不再自動幫目標
專案打正式版 tag。**

## 為什麼改

`docs/PIPELINE_REDESIGN.md` §5.1 原本的設計是：合併完 PR 之後，AITeam 直接
在正式分支的合併 commit 上打一個版號 tag（例如 `v0.12.1`）並推上 GitHub。
這個設計是在 governance 2.0/2.1 之前就有的。

governance 2.0/2.1 幫 AITeam 自己訂了「正式發布（tag + GitHub Release）
必須由使用者明確觸發，不能因為一般合併就自動發生」的規則，但當時只處理了
AITeam 自己的 GitHub Actions（`build-windows.yml`/`release-windows.yml`）。
沒注意到 AITeam 的 change task pipeline，本身也會對**任何**它管理的專案
（包含 AITeam 自己，如果之後把 AITeam 登錄成自己的專案）做一樣的事——
每完成一個任務就自動蓋一次正式版號，而大部分任務其實只是過程中的修改，
不需要每次都變成一個「正式版」。

跟專案負責人確認後，原則統一為：**版號數字（VERSION／BUILD）照常在每次
任務完成、合併時更新，但 tag／Release 這個「正式發布」的身分，永遠由使用
者另外明確觸發才建立**——不管目標專案是 AITeam 自己還是其他 managed
repository，一視同仁。

## 改了什麼

- `ChangeTaskService.RunAsync`：合併 PR 之後，移除自動建立 git tag、推送
  tag 的步驟。現在流程就停在「合併完成、同步本機」，不再多做正式化的
  最後一步。
- `ChangeTaskResult` 拿掉 `Tag` 欄位（不再有意義，因為不會自動建立）；
  `MainWindow` 顯示的完成訊息也跟著改成只顯示版本號。
- PR 內文與進度訊息裡，還是會顯示「未來正式發布時建議的 tag 是什麼」，
  純粹給人看的資訊，不代表已經建立。
- 補上 `PROJECT_RULES.md` §7 的一個缺口：原本只講不自動發布 GitHub
  Release，沒有明講不自動打 tag，這次一起講清楚（詳見
  `GOVERNANCE_CHANGELOG.md` 2.2.0）。

## Build 1（同一版號的第二次修正，未升版號）

實測 v0.13.1 時，v0.12.1 原本想修的「視窗非最大化時，左半邊卡片右緣被切
到」這個問題還是沒解決。這屬於「同一件事還沒修好、繼續修」，照新版號制度
不升 `VERSION`，改成 `BUILD` 從 0 加到 1（顯示成 `V0.13.1 Build 1`）。

- 換了一個不同角度的修法：不是加邊界間距，而是在視窗第一次顯示完成後，
  用「把視窗寬度加 1 再改回來」這個小技巧，強制 WinForms 依照最終正確的
  DPI 縮放結果重新排版一次。原本懷疑的成因是：在螢幕縮放比例不是 100%
  的電腦上，視窗剛顯示時的第一次排版計算，用的尺寸還沒完全套用正確的
  DPI 縮放，等到真的縮放套用後沒有整個重新排版，導致卡片邊框照舊的（較
  寬的）尺寸畫出來，超出實際邊界被裁掉；最大化會強制重新排版一次所以看
  起來正常。
- v0.12.1 加的中間留白（gutter）維持不動，兩個修法不衝突。
- 這個原因是根據程式碼推理、無法在這個環境實際跑 Windows 驗證，仍需要
  實測確認。

## Build 2（同一版號的第三次修正，未升版號）

實測回報：Build 1 修好了按鈕／下拉選單被裁到文字的問題，但「執行進度 /
結果」那個 log 文字框，中英文混排時行高行距還是不一致，看起來一行高一行
低，跟原本猜測的成因（`RichTextBox.DetectUrls` 或每次貼字都重設
`SelectionFont`）無關——那兩個修法在 Build 0（v0.12.1）就做了，沒有效果。

重新看螢幕截圖後找到更直接的成因：這個文字框原本用的字型是
**Consolas**，這是一套純西文等寬字型，**完全沒有中文字的字樣**。log 內容
中英文夾雜時，遇到中文字，Windows 會自動「借用」系統裡別的字型來畫那些
中文字（字型代換／font fallback）。代用字型跟 Consolas 的字高、行距量測
方式不一樣，所以中文字比較多的那幾行，跟純英文的那幾行，畫出來的行高就
不一致——這才是行高行距亂掉的真正原因。

- 修法：把 log 文字框的字型從 `Consolas` 改成
  `Microsoft JhengHei UI`（跟畫面其他地方用的字型一樣，本身同時支援中
  文與英文字母數字，不需要借字型，行高自然統一）。
- 這屬於同一個「行高行距」問題的第三次修正嘗試，不是新問題，所以只把
  `BUILD` 從 1 加到 2（顯示成 `V0.13.1 Build 2`），`VERSION` 不變。
- 這個原因一樣是根據程式碼推理、無法在這個環境實際跑 Windows 驗證，仍
  需要實測確認。

## 目前還沒做的事（先誠實記錄）

現在如果要正式把 CYAccounting 這類「AITeam 管理的其他專案」標成某個正式
版本，AITeam 沒有內建的按鈕可以做這件事了（跟 AITeam 自己有
`release-windows.yml` 不一樣）。如果之後需要，屬於一個新功能，要另外討論
設計。目前只能請使用者自己手動在 GitHub 上建立 tag／Release，或之後再請
AITeam 加上對應功能。
