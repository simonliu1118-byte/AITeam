# V0.18.0

修改流程檢查後找到的兩個缺口，這一版補上。

## 1. 停止任務按鈕

### 問題

任務一旦送出，唯一能停下來的方式是**關掉整個程式**。修改任務動輒十幾二十分鐘，中途發現方向不對、
或某個 AI 卡住不動，使用者只能強制關閉；高風險任務更會停在「等你到 GitHub 手動合併」，
那是一個**沒有逾時的無限等待**，決定不合併就永遠卡住。

### 改了什麼

- 送出按鈕旁邊新增「停止」，只有任務執行中才可以按，按下會先確認。
- 每一次任務有自己的 `CancellationTokenSource`，接在程式生命週期底下（關程式一樣會取消）。
- 取消會一路傳到 `ProcessRunner`，它本來就會 `Kill(entireProcessTree: true)`，
  **所以按下去是真的結束正在跑的 CLI**，不是只把畫面切回待命。
- 等待人工合併的迴圈本來就會檢查取消旗標，所以高風險任務也停得下來。
- 中止後歷史任務會記成「已取消」；已經改過的檔案留在隔離工作區，不會合併、也不會動到本機專案。

## 2. 送出前的前置檢查

### 問題

`VERSION` 檔的檢查原本是在**升版號**那一步才做——那時候調查、規劃、實作、兩輪審查全部跑完，
AI 額度早就燒掉一大半，才告訴使用者「這個專案沒有 VERSION 檔，做不下去」。

### 改了什麼

新增 `ProjectPreflight`，分成兩個時機：

**送出前（主畫面）**
- **擋下來**：沒有任何 AI 上線、找不到本機 Repo、找不到專案目錄 → 跳提示，不送出。
- **只提醒**：只有 1 個 AI 上線（查詢可以、修改需要 2 個）、`VERSION` 檔缺少或格式不對
  （查詢不受影響）、Repo 還沒有 GitHub Actions → 寫進執行紀錄後照常進行。

**修改管線開頭（`ChangeTaskService`）**
- 在**建立工作區、派出任何 AI 之前**先檢查 `VERSION`，有問題立刻停，一點額度都不會浪費。
- `BumpVersionAsync` 保留同一份檢查當最後一道防線（實作階段有可能把 VERSION 改壞或刪掉）。

## 測試

`ProjectPreflightTests`：完整專案沒有任何提醒、沒有 AI 是 Blocker、只有一個 AI 只是 Warning、
找不到 Repo 會直接擋下並停止後續檢查、缺 VERSION 只是 Warning、以及 `X.Y.Z` 格式的各種寫法判斷。
