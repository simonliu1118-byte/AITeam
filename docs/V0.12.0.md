# AITeam v0.12.0

Sixth implemented step of `docs/PIPELINE_REDESIGN.md` (§5.1): formalization no
longer pushes straight to the target project's default branch. It now opens a
PR, waits for that project's own CI, and only merges automatically for
LOW/NORMAL risk — HIGH risk waits for a human.

## Changes

- **PR instead of a direct push.** After Final Review PASS and the version
  bump/commit, AITeam pushes the task branch (`aiteam/task-<id>`) to `origin`
  and opens a PR against the project's default branch via `gh pr create`
  (title/body include the request, version, risk level, and the
  Implementer/Challenger/Final Reviewer for that run). This replaces the old
  `git push --atomic` straight to the default branch.
- **CI gate.** AITeam waits on the PR's checks (`gh pr checks --watch
  --fail-fast`). On failure, the Implementer gets the check summary and
  fixes it in the same worktree; the fix is committed and pushed to the same
  branch (updating the PR in place), then AITeam waits again. Bounded by a
  new `workflow.max_ci_repair_rounds` setting (default 3, alongside the
  existing `max_repair_rounds`) — if it's still red after that many rounds,
  AITeam stops and leaves the PR open with a link, rather than merging
  broken code or looping forever.
- **Risk-gated merge.** Once CI is green:
  - LOW / NORMAL risk → AITeam merges the PR itself (`gh pr merge
    --delete-branch`, strategy from the new `ProjectEntry.merge_strategy`
    field — `merge`/`squash`/`rebase`, defaulting to a plain merge commit).
  - HIGH risk → AITeam leaves the PR open and polls `gh pr view --json
    state` until a human merges it (or reports if it gets closed instead),
    rather than merging on its own.
- **Effective risk.** Per §4.1's last bullet, when the task ran in degraded
  2-AI review mode, a LOW risk classification is bumped to NORMAL before the
  merge-gating decision — reduced independent review is itself a risk
  factor. This is the first version where `Risk` actually drives behavior
  (previously it was only ever displayed).
- **Tagging moves after the merge.** The tag now points at the actual merge
  commit on the default branch (fetched after `gh pr merge`/human merge),
  not at the local worktree's pre-merge commit — correct for squash/rebase
  strategies where the merged commit's SHA differs from what AITeam
  produced locally.
- Local cleanup: once a task is formalized, AITeam now also deletes the
  local `aiteam/task-<id>` branch in the project's repo (previously only the
  worktree was removed), since the branch is real remote-tracked history now
  instead of a throwaway local ref.

## Known limitation (by design — see PIPELINE_REDESIGN.md §5.2, not yet built)

This version assumes the target project **already has a working CI
workflow**. If it doesn't, `gh pr checks` finds nothing to watch, the CI gate
never passes, and the task will exhaust `max_ci_repair_rounds` and stop with
the PR left open. Auto-bootstrapping a minimal CI workflow when none exists
is §5.2 of the spec and is the next version to implement — until then, only
use this against projects that already have CI configured.
