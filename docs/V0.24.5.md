# V0.24.5

實測回報的三件事。

## 1. 「正在發言…」沒有被換掉（真的 bug）

畫面上會同時出現：

```
第 1 輪 · GPT / Codex
正在發言...
第 1 輪 · GPT / Codex · 用時 00:09
以一般工程判斷……
```

佔位的那一段應該在發言回來時被整段刪掉，但沒有。

**原因**：逐字稿是**唯讀**的 RichTextBox，而唯讀的 RichTextBox 會**直接忽略**
`SelectedText` 的指派——刪除指令等於沒有執行，所以舊內容原封不動留著。

**修法**：刪除前暫時解除唯讀，刪完再設回去。

## 2. 「送出後仍可在上面輸入補充，按「補充...」被截斷

那一欄的寬度被「停止」「送出」兩顆按鈕吃掉不少，原本的句子放不下。
依照「不要出現被截斷的文字」的原則，把句子縮短：

- 待命時：**執行中可繼續輸入補充**
- 執行中：**輸入補充後按「補充說明」**

## 3. 結果摘要只是最後一個人的發言

以前直接把**最後一位發言者**的內容當摘要。但最後講話的人不見得代表這場會議的結論——
如果他只是補一句話，摘要就變得莫名其妙。

改成寫**每個人最後的立場**：

```
共 2 輪 · 呼叫 5 次

● GPT / Codex：看完大家的說法，我改口支持維持 SQLite
● Claude：我主張維持 SQLite
● Gemini / Antigravity：……
```

同一個 AI 只取它**最後一次**的發言（先前的立場已經被自己後來的發言取代），
使用者自己的發言與失敗／被跳過的那幾則都不算。

### 順帶：「結束會議」不再記成「已取消」

開完會就是開完了，按「結束會議」記成「已取消」不合理。改成：**只有一個 AI 都沒講到話
就關掉**才算沒完成。
