# V0.22.0

## 人工合併搬進 AITeam

### 問題

高風險變更（以及受限模式下的所有變更）不會自動合併，必須由人確認。但這一關以前是
**AITeam 開完 PR 之後就開始輪詢，等使用者自己開瀏覽器去 GitHub 上按合併**。
整套流程只有這一步要離開 AITeam。

而且那個等待是**沒有逾時的無限迴圈**：決定不合併的話，任務就一直卡在那裡。

### 改了什麼

改成在 AITeam 裡跳出一個確認視窗。**判斷需要的東西一起搬進來**，不是叫使用者盲按：

- 專案、版本、風險等級、把關強度
- **改了哪些檔案、各改幾行**（`git diff --stat`）
- **CI 檢查結果**
- **最終審查的結論**
- PR 連結（還是可以點過去用瀏覽器看完整 diff）

三個按鈕：**合併這個 PR** / **暫不合併** / **在 GitHub 上開啟**。

- 「暫不合併」：PR 與分支都保留在 GitHub 上，任務正常結束（不算失敗），之後可以自己處理。
- 視窗被直接關掉：當成「暫不合併」。**不合併可以反悔，合併不行**，預設一定要是保守的那一邊。
- 按下合併之前會先查一次 PR 狀態：如果使用者剛才自己跑去 GitHub 上合併了，就不會重複執行；
  如果 PR 已經被關掉，會明確報錯而不是硬合。

自動合併的路徑也改走同一個函式，所以同樣不會對已處理完的 PR 重複動作。

## 歷史紀錄：同一個清單 + 類型 + 篩選

會議功能即將加入，歷史紀錄要怎麼分——分頁籤，還是同一個清單加類型欄位？

**選了同一個清單**，理由：

- 你記得的通常是「那件事」，不是「那是任務還是會議」；照時間排一起看最直覺。
- 會議常常是任務的前身（先開會 → 定案 → 派工），放在一起才看得到前後關係。
- 分頁籤沒辦法「全部一起看」，篩選可以——篩選是頁籤的超集合。

所以：每一列多顯示類型（查詢／修改／會議），清單上方一個篩選下拉（全部／查詢／修改／會議）。

同時新增 `TaskKind.Meeting`，先把位子留好；`TaskStages.For()` 讓會議借用查詢的兩格，
畫面不會空掉。
