# V0.19.0

## 串流讀取：實作階段不再是沒有動靜的黑洞

### 問題

`ProcessRunner` 以前用 `ReadToEndAsync`——**把 CLI 跑完、一次收走全部輸出**。
在那之前，AITeam 對這家 AI 正在做什麼一無所知。修改任務的實作階段可能跑十幾分鐘，
畫面上完全沒有動靜，使用者無法判斷它是在認真改，還是已經卡死。

這也是「任務執行中沒辦法插話」的根本原因：AITeam 的動作粒度太粗，
一個階段就是一次呼叫，中間沒有任何可以插進去的空隙。

### 改了什麼

**`IProcessRunner.RunAsync` 新增 `onOutputLine` 回呼**（選填，不傳就是以前的行為）。
`ProcessRunner` 改成逐行讀 stdout 與 stderr：一邊累積完整輸出，一邊把每一行往外送。

**新增 `ProviderActivity`**，把 CLI 的原始輸出行翻成一句「現在在做什麼」：

| AI | 輸出形式 | 看得到什麼 |
|---|---|---|
| GPT / Codex | 給人看的純文字進度 | 直接顯示該行（去掉空行與純裝飾線） |
| Gemini / Antigravity | NDJSON 事件 | 優先抓工具名稱（`使用工具：read_file`），其次抓階段名稱 |
| Claude | 目前用 `--output-format text` | **過程中不會印任何東西**，只有最後的答案，所以還看不到即時進度 |

Claude 要有即時進度必須改成 `--output-format stream-json`，那會一併改動答案的解析方式，
風險較高，留待之後單獨處理。

**畫面**：「目前任務」卡片的階段說明下方新增一行淺灰色的即時活動，換階段時自動清空，
任務結束時隱藏。這一行**不寫進執行紀錄**——訊息量太大，寫進去會把紀錄洗掉。
更新節流到每 120ms 一次，避免每秒好幾行把 UI 執行緒灌爆。

### 連帶的好處

- CLI 講到一半被逾時或使用者中止時，**前面已經吐出來的內容還在**，不再整段丟掉。
- 有了即時畫面，才有辦法判斷一家 AI 是「在想」還是「卡住」——這是之後要做的軟逾時的前提。

## 測試

`ProviderActivityTests`：純文字進度照原樣顯示、空行與裝飾線跳過、工具名稱優先（含巢狀一層）、
沒有工具名稱時退回階段名稱、`text_delta` 這種雜訊不顯示、壞掉的 JSON 跳過而不是丟例外、
過長的行會縮短到一行放得下。
