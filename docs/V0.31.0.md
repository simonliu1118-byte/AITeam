# V0.31.0

## 可以開新專案了

以前 AITeam 只會管理「已經存在的專案」：選位置的那棵樹只列出 GitHub 上已經有的資料夾，
新專案沒有資料夾就選不到；就算選了一個現有資料夾，只要根目錄沒有 VERSION 檔，修改任務
也會在開工前被擋下。兩件事加起來，等於**不可能從 AITeam 開一個新專案**。

### 管理專案：＋ 新增資料夾

「專案在 Repo 內的位置」多了一顆「＋ 新增資料夾」：選好要放在哪一層底下，按下去、取名字。
新資料夾在樹上顯示為「名稱（新）」，選到它時會標明「新資料夾，第一次修改任務時建立」。

**資料夾只是先登記，不會當場建立。** 原因有兩個：

1. git 不保存空資料夾，當場建立了也送不上 GitHub。
2. AITeam 對 Repo 的任何改動都要經過分支、PR、CI 和你按合併。

所以真正建立是在**第一次對這個專案送出修改任務時**，資料夾跟著那次的修改一起進 PR。
合併之後資料夾就真的存在了，「新專案」的標記也自然失效。

名稱會先檢查（用 Windows 的規則，不是執行環境的規則）：不能有 `\ / : * ? " < > |`、
不能用空白或句點開頭結尾、不能是 `CON`、`NUL` 這類保留名稱、同一層不能重名；一次只建一層。

我考慮過另一個做法——「先存在本機，之後再指定 GitHub 位置」——沒有採用：AITeam 的每一次
修改都是開分支、送 PR、跑 CI、你按合併，這一整套都建立在「專案在 GitHub 上」。只存本機的
專案等於這套保護全部失效，之後補指定位置還要處理本機跟 GitHub 對不上的問題。

### 還沒有 VERSION 檔：問你要從哪一版開始

依共用規則，版號第一碼是你的決定，所以 AITeam **不會自己挑一個數字寫進去**。修改任務開工前
（還沒花任何 AI 額度）會跳出視窗問你起始版號，預設 0.1.0；你填的版號就是這次發行的版號，
不會再往上加。按「先不要做」任務就不開始。

這同時適用於**新專案**和**一直沒有 VERSION 的舊專案**（例如 CYInvoice）。舊專案如果實際上
早就是 2.x，填 2.x 就好。

VERSION 內容**不對**（例如 `1.2.3-beta`）的情況不變：照舊擋下，不會猜。

### 其他配合的地方

- 新專案送出任何需求都直接當成修改任務——還沒建立的專案沒有東西可以查。
- 開會時如果選了新專案，AI 會看整個 Repo 來討論（它自己的資料夾還不存在）。
- 交給 AI 的專案說明會講清楚「這是新專案、資料夾是這次才建立的」，
  不然 Scout 看到空資料夾只會回報「什麼都沒有」。
- **只有明確標記過的新專案**才會被當成「待建立」。一個原本存在、後來被刪掉或改名的專案目錄，
  照舊擋下，絕對不會被悄悄重新建立。
