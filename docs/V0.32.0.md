# V0.32.0

## 分工依成本重排，而且可以自己改

### 新的預設分工

原則：**便宜的做大量閱讀，GPT 做最吃額度的實作，最貴的 Claude 只做份量少但需要判斷的事。**
（成本排序依使用者的方案：Claude > GPT > Gemini；Gemini 最便宜，但實作能力有限。）

| 角色 | 以前 | 現在（排在前面的優先，沒上線就往後找） |
|---|---|---|
| Scout 偵察 | Gemini → GPT → Claude | Gemini → GPT → Claude（不變） |
| Planner 規劃 | GPT → Gemini → Claude | **Claude** → GPT → Gemini |
| Implementer 實作 | Claude → Gemini → GPT | **GPT** → Claude → Gemini |
| Challenge 挑戰 | 跟實作不同家：Gemini → GPT → Claude | 跟實作不同家：Gemini → **Claude** → GPT |
| Final Review 最終審查 | 跟前兩位不同家：GPT → Gemini → Claude | 跟前兩位不同家：**Claude** → GPT → Gemini |

三家都上線時，實際分工是：偵察 Gemini、規劃 Claude、實作 GPT、挑戰 Gemini、最終審查 Claude。

**Gemini 在實作候補排最後**，兩個原因：它在我們這邊明顯最慢；實作會在「審查修正」和「CI 修正」
裡被反覆呼叫，而 Google 對 Antigravity 的使用條款特別提到不要跑大量自動迴圈。偵察（每個任務一次）
和挑戰（最多四次）用它比較合適。

規劃和最終審查都是 Claude，看起來像「自己審自己的計畫」，但以前也是這樣（兩個都是 GPT）。
負責質疑計畫的是中間的 Challenge，這一點沒變。

### 可以在設定檔改

`settings.json` 的 `workflow.roles`，名字可以寫 `claude`、`gpt`（或 `codex`）、`gemini`
（或 `antigravity`、`agy`）：

```json
"roles": {
  "scout": ["gemini", "gpt", "claude"],
  "planner": ["claude", "gpt", "gemini"],
  "implementer": ["gpt", "claude", "gemini"],
  "challenger": ["gemini", "claude", "gpt"],
  "final_reviewer": ["claude", "gpt", "gemini"]
}
```

- 沒寫 `roles`，或沒寫某個角色，就用上面的預設。
- 只寫了一兩家也沒關係，沒寫到的照預設順序補在最後。寫漏一家不該讓它永遠選不到，
  否則其他人沒上線時，任務會因為「找不到可用 AI」而失敗。
- 認不得的名字略過，重複的只算一次。

換分工本身就是一種實驗：哪天覺得換回來比較好，改設定檔就好，不用等新版本。

### 沒有變的

- 「查詢還是修改」的判斷、會議、定案書的人選都不受影響，這次只動修改管線的五個角色。
- 把關強度的規則（2 家時 LOW 升 NORMAL、1 家時一律 HIGH）不變。
