# V0.29.0

## 會議送去執行之前，先寫一份定案書

### 以前送出去的是什麼

按「送去執行」時，交給修改管線的是這段：

```
共 3 輪 · 呼叫 9 次

● GPT：（最後一次發言，壓成一行，砍到 220 字）…
● Claude：（同上）…
● Gemini：（同上）…
```

三個問題：

1. **那不是結論，是三個立場並排。** 三家意見不同時（討論的價值就在這），接手的 AI
   拿到三段互相打架的話，沒有任何一句說「所以決定怎麼做」。
2. **每段砍到 220 字。** 真正有用的部分——哪個檔、怎麼改、為什麼不用另一個做法——
   通常就在被砍掉的後半。
3. **我們還告訴 Planner 那是「已經由使用者確認」的定案，「不要重新討論」。**
   這是在騙它。它不會回頭問，因為我們叫它不要問。

另外，「要送出的需求」跟「會議結論」以前填的是同一份文字，等於同一段話送兩次。

### 現在的流程

按「送去執行」→ 先問你要不要寫定案書：

- **寫定案書再送**（預設）：選一家 AI，一次呼叫，把整場會議寫成五段。
- **不用，直接送**：照舊送討論摘要，但措辭會誠實（見下）。
- **取消**：留在會議裡。

不硬性規定一定要收斂——有時候第一輪就講得很清楚了，硬要多跑一次只是多花時間。

### 定案書的五段

```
要做什麼：
為什麼這樣做：
具體做法：
明確不做／已經排除的選項：
還沒決定的事：
```

**最後一段是關鍵。** 會議談到一半就送出時，沒談完的部分會被老實列出來，而且
交給 Planner 的背景會明講「那一段是尚未定案的，遇到那些問題要先問使用者」。

### 誰來寫，以及偏袒問題

寫的人剛剛才在會議裡表過態，一定有偏向自己立場的風險。三道防線：

1. 提示裡明令它現在是**會議記錄者**：不准替自己辯護，分歧沒解決就寫進「還沒決定的事」，
   不准偷偷選邊。
2. 定案書上**標明是誰整理的**，你才知道要用什麼眼光檢查。
3. 交接視窗裡那份**可以直接編輯**——送出去的是你看過並同意的版本。

預設順序 Claude → GPT → Gemini（Gemini 光啟動就比另外兩家慢很多，不適合放在你等著
送出的路徑上），下拉選單可以當場換。

定案書**只讀逐字稿、不准讀專案檔**：這樣才快，也才不會加出逐字稿裡沒講過的東西。

### 不再對 Planner 說謊

背景怎麼介紹自己，交由 `MeetingConclusion.ComposeBackground()` 決定：

| 送出的東西 | 對 Planner 的說法 |
|---|---|
| 定案書 | 「已經由使用者確認，不要重新討論；但『還沒決定的事』那段要先問使用者」 |
| 未收斂的摘要 | 「**這場會議沒有收斂出定案**，下面只是每位最後的立場，可能互相矛盾，有疑問就先問」 |

交接視窗的標題也跟著改：沒收斂時會直接標 ⚠。

### 其他

- 「要送出的需求」改成一句短的（可改），不再跟結論重複。
- 歷史紀錄存的是定案書，不是程式湊出來的立場並排；逐字稿也會附上定案書。
- 寫定案書時可以按「停止」中止；失敗會問你要不要改成直接送，選「否」就留在會議裡換一家再試。
