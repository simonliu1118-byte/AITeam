# V0.24.0

## 1. 三家 AI 只有 Claude 收得到議題（真正的 bug）

### 症狀

四方會議送出議題後：

```
GPT / Codex 這一輪失敗：exit 1｜Failed to read prompt from stdin:
input is not valid UTF-8 (invalid byte at offset 211).
```

Claude 正常回答，Codex 與 Gemini 都拿不到議題。

### 原因

`ProcessRunner` 建立行程時指定了 `StandardOutputEncoding` 與 `StandardErrorEncoding` 是 UTF-8，
**但沒有指定 `StandardInputEncoding`**。沒有指定時 .NET 會用系統的 ANSI 代碼頁——
在繁體中文 Windows 上是 **CP950**。提示裡只要有中文，寫進 stdin 的位元組就不是合法的 UTF-8，
CLI 一讀就拒絕。

**為什麼只有 Claude 沒事**：三家傳提示的方式不一樣。

| AI | 提示怎麼進去 | 受影響？ |
|---|---|---|
| GPT / Codex | **stdin** | ✅ 中招 |
| Gemini / Antigravity | **stdin**（stream-json） | ✅ 中招 |
| Claude | **命令列參數** `-p "..."` | ❌ 沒事 |

offset 211 正好是提示裡第一個中文字的位置——前面都是英文所以沒事。

### 這同時解釋了更早的一件事

先前有一次「GPT / Codex 本次失敗，嘗試下一個 AI」，當時查不出原因（失敗訊息根本沒被寫出來，
那是 V0.16.1 才修的）。**幾乎可以確定就是同一個 bug**：只要提示裡有中文，Codex 就收不到。
會議功能把它暴露出來，是因為會議一次三家都問，對照組很明顯。

### 修法

```csharp
StandardInputEncoding = standardInput is null ? null : new UTF8Encoding(false)
```

不含 BOM——BOM 會被 CLI 當成內容的一部分。

建立 `ProcessStartInfo` 的部分抽成 `ProcessRunner.CreateStartInfo()`，這件事才測得到。

## 2. 把關強度移到右上角，待命移到目前任務旁

原本「把關強度：降級模式（2 個 AI 可用）· 實作一個，挑戰與……」是一長串文字塞在 AI 狀態下方，
自動縮到幾乎看不到。

- **右上角**改成徽章，只寫 **完整模式／降級模式／受限模式**，顏色跟著走（綠／橘／紅），
  **詳情放 tooltip**（滑上去才顯示「3 個 AI 可用。三個 AI 分別負責……」）。
- **待命／執行中**移到「目前任務」標題列旁邊——它講的本來就是目前任務的狀態。

## 3. 發起會議改成獨立樣式，放到產品名稱旁

會議跟「送任務」是不同性質的功能，混在 AI 狀態那排普通按鈕裡不合適。
改成實心強調色的膠囊（＋ 發起會議），放在 AITeam 標題右邊。

## 4. 會議視窗的欄位對齊

「專案／模式／規模」三個標籤比旁邊的下拉低了一截：標籤用 `Anchor = Left` 垂直置中，
卻又多給了 7px 的上邊界，等於置中後再往下推。改成上下邊界 0；
三個下拉統一設定；「開始會議」按鈕高度改成跟下拉一致。

## 5. 看得到誰在發言，而且隨時可以跳過或停止

以前狀態列只寫「第 2 輪 · 發言中… 已經 00:47」，看不出是誰；而且「跳過這家」要等軟逾時
（3 分鐘）才會出現。

- 有人發言時就一直顯示一條列：**「Claude 正在發言…」** ＋ **跳過這家** ＋ **停止這一輪**，
  不必等超時。
- 狀態列改成「第 2 輪 · Claude 發言中 00:47（正在讀檔…）」，帶上發言者與它當下的動作。
- 軟逾時到了不再是「才出現按鈕」，而是這條列**變成警示色**並多一顆「繼續等」。
- **停止這一輪**：目前這家中斷，後面排隊的也不再發言，但會議本身還在，
  可以接著補充、定案或結束。

## 6. 失敗或被跳過的發言不進逐字稿

那幾則的內容是「（這一輪失敗，沒有發言。）」，留在逐字稿裡只會變成雜訊，
還可能被後面的 AI 拿去發揮。

## 測試

- `ProcessRunnerStartInfoTests`：stdin 一定是 UTF-8 且不含 BOM、沒有 stdin 時不做轉向、
  輸出也以 UTF-8 讀、參數逐一傳遞。
- `MeetingServiceTests` 新增：失敗／跳過的發言不會出現在後續提示裡。
