# AITeam v0.9.0

Third implemented step of `docs/PIPELINE_REDESIGN.md` (§4.4, §4.5): the version
bump level is now reconfirmed against the actual diff instead of only trusting
Plan Gate's pre-implementation guess.

## Changes

- **Final Review reconfirms the version bump.** `BuildFinalReviewPrompt` now
  requires a second line — `AITeamVersionBumpConfirm: PATCH|MINOR|MAJOR` — where
  the Final Reviewer classifies the bump level against the diff actually
  produced, instead of `ChangeTaskService` blindly reusing Plan Gate's
  pre-implementation guess. If the reviewer's confirmation differs from the
  plan (implementation or repair rounds can widen scope), the confirmed value
  wins and the change is logged (`Plan Gate：PATCH → Final Reviewer：MINOR`,
  etc.). If the reviewer omits the line or it can't be parsed, AITeam falls
  back to Plan Gate's original value — never worse than before this change.
- **Version-file edit no longer needs Final Review's attention.** The prompt
  now tells the reviewer that AITeam applies a purely mechanical version-file
  edit after a PASS, based on their own `AITeamVersionBumpConfirm` value, and
  that they don't need to re-review that follow-up edit — avoiding an extra
  LLM round trip for what is a single-line, deterministic change.
- Added `ParseVersionBumpConfirm` (internal, unit tested) mirroring
  `ParseVersionBump`'s parsing but reading the reviewer's confirmation line.

See `docs/PIPELINE_REDESIGN.md` for the full plan and remaining items.
