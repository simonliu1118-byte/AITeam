# AITeam v0.11.0

Fifth implemented step of `docs/PIPELINE_REDESIGN.md` (§三): the Plan Gate ⇄
使用者討論迴圈, replacing the old one-shot Plan Gate call with an uncapped
discussion loop and a mandatory user confirmation before a change is
finalized.

## Changes

- **Plan Gate now discusses instead of guessing.** Each Plan Gate reply
  starts with `AITeamPlanStatus: NEEDS_INPUT` (followed by concrete
  questions) or `AITeamPlanStatus: READY` (followed by the usual
  `AITeamRisk` / `AITeamVersionBump` lines and the plan). There is no round
  cap — Plan Gate can keep asking as long as it judges the plan isn't well
  defined yet.
- **Every finalization goes through the user, even a self-declared READY.**
  When Plan Gate decides it's ready on its own, AITeam shows the full plan
  and asks "還有沒有要補充？" before moving on. The user can confirm and
  start execution, add a supplement (which goes back into the discussion
  and Plan Gate re-evaluates — it may stay READY with an updated plan, or
  drop back into NEEDS_INPUT if the supplement raises new uncertainty), or
  hand off to the AI to finalize immediately.
- **"交給 AI 全權判斷" is the one forced-exit path.** At either stage the
  user can delegate the remaining decision to Plan Gate; the next Plan Gate
  call is instructed to output READY unconditionally, and if triggered from
  the confirmation stage it finalizes immediately without asking again.
- **`baseSha` is now re-locked at the moment the plan actually finalizes**,
  not when the task starts. Since Scout and Plan Gate only read the
  worktree (no edits are made before implementation), AITeam re-syncs the
  project's default branch after finalization and, if GitHub moved during
  the discussion, discards and recreates the still-empty worktree against
  the new commit before handing off to the Implementer. This means a long
  discussion no longer causes the final "did origin move during the task"
  push-race check to fail just because time passed — only a genuine change
  made *after* the plan was locked in still trips it.
- `ChangeTaskService.RunAsync` and `InquiryService.RunAsync` both gained an
  `askUser` delegate parameter (`Func<PlanGatePrompt, CancellationToken,
  Task<PlanGateResponse>>`) that the caller must supply.
- Added a modal `PlanGateDialog` (`src/AITeam.App/PlanGateDialog.cs`) reusing
  MainWindow's existing card/button visual language, and
  `MainWindow.AskPlanGateAsync` which shows it and maps a cancelled dialog
  to `OperationCanceledException`. The worktree stays alive for as long as
  the discussion takes — there's no time pressure since it's local and
  doesn't consume any remote/CI resources.
- Added `IsPlanGateNeedsInput` / `ExtractPlanGateBody` (internal, unit
  tested) alongside the rewritten `BuildPlanPrompt`, which now takes the
  running discussion transcript and a `mustFinalize` flag.

See `docs/PIPELINE_REDESIGN.md` for the full plan — next up is §5 (PR +
target-project CI + risk-gated merge formalization), the largest remaining
item.
