# V0.24.3

## Gemini 一輪想了 9 分鐘

實測：三百字的簡短討論，Gemini / Antigravity 跑了 9 分多鐘還沒講完，
狀態列顯示它在 `list_dir`——也就是**在掃專案目錄**。

### 有兩個原因，其中一個是我寫的提示造成的

**1. 提示要它讀檔，卻沒說該讀多少。**

原本選了專案時，提示只有一句：

> You have a read-only copy of this project. Open the actual files before making claims about it.

「打開實際檔案再下判斷」是對的，但沒有任何界線——AI 很自然就把整個 repo 掃一遍。
三百字的題目也能因此花掉十分鐘。

現在依規模給出**探索預算**：

| 規模 | 給 AI 的指示 |
|---|---|
| 簡短 | 最多看幾個明顯相關的檔案；**不要巡覽整個 repo**、不要窮舉目錄。需要更深入才能回答就直說，不要真的去做 |
| 標準 | 讀對這個問題重要的檔案就停，不要掃全部 |
| 深入 | 可以徹底調查，但拿到足以表態的資訊就停 |

**2. 硬逾時三種規模都是 15 分鐘。**

規模講的是「這一輪要投入多少」，時間上限本來就該跟著走。改成：

| 規模 | 硬逾時 |
|---|---|
| 簡短 | 5 分鐘 |
| 標準 | 10 分鐘 |
| 深入 | 15 分鐘 |

（軟逾時不變：到了只是提醒，不會中斷。）

### 另外：每位發言者實際花了多久，寫在發言標題上

```
第 1 輪 · Gemini / Antigravity · 用時 09:37
```

三家的速度差很多（Antigravity 光是啟動就比另外兩家慢一個量級），
把時間放在標題上，慢到不合理的時候一眼就看得出是哪一家、慢多少。
失敗或被跳過的那幾則也會記下等了多久。

### 還不能確定的部分

以上兩點是**我這邊確實有問題、也確實改掉了**的地方。但 Antigravity CLI 本身就比
另外兩家慢很多（健康檢查 28 秒 vs 6～8 秒），這一段不在 AITeam 能控制的範圍。

要分辨「是它本來就慢」還是「是掃專案花掉的」，最簡單的方法是**開一場不指定專案的會議**：
沒有專案就沒有檔案可掃，如果它還是要好幾分鐘，那就是 CLI 本身的速度。
