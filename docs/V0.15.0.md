# AITeam v0.15.0

任務進度顯示：右上角狀態徽章與「目前任務」階段進度條。

## 為什麼改

在這之前，任務跑起來之後畫面上只有右上角一個「待命／執行中」的小標籤，
加上左下角一行一行往下滾的 log。看不出任務走到哪一步、是哪個 AI 在做、
已經跑多久，最嚴重的是——**看不出 AI 其實已經停下來在等人回話**。

規劃階段（Plan Gate）會停下來問使用者問題，高風險變更也會停下來等人到
GitHub 上人工確認合併。這兩種情況在舊畫面上跟「AI 正在努力工作」長得
一模一樣，人可能一直乾等。

這個項目在 `docs/PIPELINE_REDESIGN.md` 第八節就被列為「之後可以一起做」
的中優先級項目，這次補上。設計方案先做成視覺稿跟專案負責人確認過才實作。

## 改了什麼

### Core：結構化階段回報

- 新增 `TaskProgress.cs`：`TaskKind`（查詢／修改）、`TaskStage`（八個階段
  代號）、`TaskActivity`（執行中／等使用者／完成／失敗），以及把階段清單與
  中文名稱集中管理的 `TaskStages`。
- `InquiryService.RunAsync` 與 `ChangeTaskService.RunAsync` 新增一個
  `Action<TaskProgress> onStage` 參數，在每個階段轉換點回報結構化狀態。
  原本一行一行的純文字 `progress` log **完全不變**，兩者並存：log 給人看
  細節，結構化回報給畫面畫進度。
- 修改任務的七個階段直接對應管線實際流程：準備、調查、規劃、實作、審查、
  驗證、合併。查詢任務只有兩個：準備、查詢。

### 畫面：兩個位置

- **右上角徽章**（`StatusBadge`）：圓角底色＋狀態燈點＋文字，寬度依內容
  自動調整（原本固定 74px 只塞得下兩個字）。狀態有待命（綠）、執行中
  （琥珀，顯示「實作中 4/7」）、**等你回覆**（藍色加外框）、已完成、失敗。
- **「目前任務」卡片**：新增階段進度條（`TaskStageStrip`，已完成打勾、
  進行中實心放大、未開始空心，圓點下方是階段名稱），以及下方一行「誰在做
  什麼」，右上角顯示「本階段 mm:ss · 總共 mm:ss」。

### 等你回覆時閃工作列

`等你回覆` 狀態出現時，如果使用者當下已經切到別的程式（`Form.ActiveForm`
為 null），呼叫 Windows 的 `FlashWindowEx` 閃爍工作列圖示，直到切回視窗
為止。人在畫面前時不會閃，不打斷工作。任務結束（完成或失敗）時若使用者
不在這個程式，也會閃一次。

## 跟設計稿不同的地方

設計稿在「等你回覆」狀態畫了一顆「回到問題視窗」按鈕。實作時發現這顆按鈕
沒有意義：Plan Gate 的問題視窗是**強制回應視窗**（modal），出現時本來就
蓋在最上層、也擋住主視窗操作，沒有「回去」這件事可做。因此沒有實作這顆
按鈕。高風險合併等待是唯一「人真的要去別的地方（GitHub）」的情況，目前
先用文字說明 PR 編號，之後如果需要可以再加一顆開啟 PR 的按鈕。

## 尚待實機驗證

階段條的七個中文標籤在視窗縮小時會不會擠在一起，需要實測。當初討論時的
共識是：先照設計稿做帶文字的版本，實測真的擠再改成只留圓點、文字只顯示
目前這一步。
