# V0.27.0

## 新增「設定」視窗，第一個選項：嘗試隱藏 CLI 的主控台視窗

主畫面右上角（把關強度徽章的左邊）多了一顆「設定」。裡面放的是
**試試看、不行就關回去**性質的選項：**每一項預設都是關閉＝完全等於現在已知穩定的行為**。

### 開程式時閃一下的黑框是什麼

不是 AITeam 自己，也不是我們叫起來的 AI CLI——我們啟動 CLI 的時候本來就有帶
`CreateNoWindow`，它自己不會冒出視窗。

閃的是**孫程序**：Codex 在 Windows 上是用 PowerShell 去跑它的工具，而開程式時
AITeam 會先做一輪「AI 有沒有上線」的檢查，那一輪就會叫起 Codex，Codex 再叫起
PowerShell。孫程序怎麼開視窗，我們這邊管不到。

### 這次的做法

`CreateNoWindow` 會讓 CLI 拿到一個**屬於它自己的**新主控台，孫程序有機會另外開一個
看得見的。改成：AITeam 先幫自己配一個**隱藏起來的**主控台（`AllocConsole` 之後立刻
`ShowWindow(SW_HIDE)`），然後**關掉** `CreateNoWindow`，讓 CLI 沿用它——孫程序跟著
繼承，理論上就不會再開新視窗。

### 為什麼做成可開關，而且預設關閉

**因為這個手法不保證有效。** 孫程序如果是「指名要開一個新主控台」，誰都攔不住。
所以這次不是直接換掉原本的做法，而是：

- 勾起來 → 立刻生效（下一次叫用 AI 就是新做法），重開程式可以看開機那一下還會不會閃。
- 沒效果或反而更奇怪 → 把勾取消，**行為完全回到現在這個穩定版本**，不用換版本、
  不用改任何檔案。

### 不會停在「半套」狀態

如果隱藏主控台配不出來，`HiddenConsole.Apply` 會回報失敗、把勾自動取消、維持原本做法。
這一步是必要的：**沒有隱藏主控台卻關掉 `CreateNoWindow`，會變成每個 CLI 自己開一個
看得見的視窗**——那比現在糟得多。

另外，共用主控台之後 CLI 產生的 Ctrl+C 之類的訊號會傳到 AITeam 身上，所以同時用
`SetConsoleCtrlHandler` 忽略掉，避免停止任務時連主程式一起被關掉。

### 設定存在哪

`data/preferences.json`（`hide_cli_console`）。這份是程式自己寫回去的，不是給人手動編輯的；
讀壞了就當作預設值，不會讓程式開不起來。
