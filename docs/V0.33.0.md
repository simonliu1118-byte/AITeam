# V0.33.0

## GPT / Codex 額度用完時，可以改用備援或交給 ChatGPT 聊天人工接續

AITeam 的主軸還是自己串三家 CLI。這個功能只在一種情況出現：**輪到 GPT / Codex 動手改程式
（實作、依審查修正、依 CI 修正），它的額度剛好用完。**這時候會停下來問你三選一：

| 選擇 | 會發生什麼 |
|---|---|
| 改用備援 | 照分工設定的實作候補順序換下一家（預設是 Claude）接手，全程自動，但用的是它的額度 |
| 改用 ChatGPT 人工接續 | 走下面的工作單交接，用 ChatGPT 付費方案那份近乎用不完的額度 |
| 停止任務 | 工作區保留，額度恢復之後重新送出 |

以前遇到這種情況，整個任務直接失敗。

### 人工接續怎麼運作

1. AITeam 把**工作單**寫進任務分支的 `.aiteam/work-orders/<任務編號>.md`，推上 GitHub。
   工作單裡有需求、偵察結果、定案的計畫，以及一定要遵守的規則：只改這個分支、不合併、
   不 force push、**不改 VERSION**、先讀 AGENTS.md。
2. AITeam 跳出交接視窗，給你一段**交接文字**（有「複製」按鈕）。你貼給 ChatGPT，
   它自己到 GitHub 讀工作單、改程式、commit、push，最後把工作單的完成回報填好、
   狀態改成「已完成」。
3. 你回來按「**ChatGPT 已完成**」。AITeam 去 GitHub 檢查：
   - 分支上真的有新的 commit；
   - 分支歷史沒有被改寫（ChatGPT 是接在 AITeam 推上去的東西後面做的）；
   - 工作單**最後一段**的狀態是「已完成」（前幾次交接的回報不算）。
   沒通過就告訴你原因，視窗留著讓你處理完再按一次。
4. 通過之後，**挑戰 → 最終審查 → 版號 → PR → CI → 合併**照原本的流程走。

選了人工接續之後，**這個任務接下來的修正也都交給 ChatGPT**：
- 審查要求修正：工作單追加一段，寫上挑戰者和最終審查的意見，再交接一次。
  ChatGPT 覺得意見不成立，可以在完成回報的「反駁」欄寫理由，交回審查者重新裁決，
  跟 AI 修正時的反駁機制相同。
- CI 失敗：這時候已經開了 PR，不再把工作單放回分支（不然又得刪、又得多跑一次 CI），
  失敗摘要直接寫在交接文字裡。

### 保險

- **工作單不會進到主線**：合併前 AITeam 會把它刪掉；它留在這個分支的 commit 紀錄裡，
  PR 說明也會註明這次是人工接續。
- **ChatGPT 改了 VERSION 會被還原**：版號一律由 AITeam 在審查通過後處理。
- **Codex 用完之後，這個任務不會再找它**，挑審查者時也一樣，不然審查會因為同一個原因失敗。
- 中途換了實作的人（改用備援），而新的人剛好也是這一輪的審查者，等於自己審自己：
  風險等級拉到 HIGH，合併一定要你確認。
- 交接視窗按右上角關掉，會先問要不要停止任務，不會悄悄停掉。

### 限制

- 等 ChatGPT 的期間 **AITeam 要保持開著**。關掉的話任務就斷了，但分支和工作單都還在 GitHub 上。
- ChatGPT 要有這個 Repo 的寫入權限（跟 CY Web 的用法一樣）。
- 目前只處理 GPT / Codex 額度用完；其他 AI 用完的情況維持原本的行為。

### 額度用完怎麼判斷

Codex 失敗時，看它**全部**的錯誤輸出有沒有額度相關的字句（usage limit、rate limit、429……，
跟上線檢查用同一份清單）。以前只看第一行，而第一行常常只是 Codex 的版本資訊。
