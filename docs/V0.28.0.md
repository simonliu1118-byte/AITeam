# V0.28.0

## 會議可以跑到一半插話了

會議開始之後，**留言板永遠可以打字**——不管現在輪到誰在發言。以前有人在講的時候
輸入框是鎖住的，只能等它講完。

打好的字有兩種進場方式：

| 你做的事 | 結果 |
|---|---|
| 打完字就放著 | **下一位開口之前**自動插進逐字稿，它一開口看到的就已經包含你的話 |
| 打完字按「立刻插話」 | 目前這位**當場中斷**，帶著你的話**重講一次** |

「立刻插話」只在有人正在發言時出現，跟「跳過這家／停止這一輪」同一排；留言板是空的
就是灰的。

## 為什麼「立刻插話」是重講，而不是直接塞進它耳朵裡

先講清楚這件事做不到的部分：**三家 CLI 的提示都是一次性給進去的**。

- Claude 的提示是用 `-p` 當參數傳的，根本沒有 stdin 可以再補。
- Codex 的 `exec -` 是從 stdin 讀到結束為止，讀完就開始想，之後補什麼都沒人收。
- Antigravity 的 `--input-format stream-json` 理論上是一串事件，也許收得到第二則，
  但那要把 stdin 一直開著不關——**開著不關的風險是它可能一直等下一則而不收尾**，
  而且我這邊沒有那三個 CLI 可以先驗證。用「可能有效但可能讓它卡住」換一個功能，不划算。

所以「立刻插話」的實際做法是：**砍掉目前這位，把你的話寫進逐字稿，再請同一位重講一次。**
對使用者來說結果是一樣的（你的話它聽到了、它的回答考慮了你的話），而且三家行為一致、
不依賴任何一家 CLI 的未驗證行為。

它講到一半的內容**不留**——那段是在沒看過你的話的前提下講的，留著只會跟重講的版本
互相矛盾。但逐字稿會留一行說明是你插話了，畫面上不會莫名其妙少一段。
