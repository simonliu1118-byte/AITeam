# AITeam v0.15.1

實測 v0.15.0 後的三項修正。

## 1. Claude 超過限額時被誤判成「錯誤」

實測時 Claude 明明是用量超過限額，畫面上卻顯示紅燈「錯誤」。查下去發現兩個
問題疊在一起：

- **關鍵字比對漏掉機器代碼寫法。** 判斷用的關鍵字表寫的是給人看的句子
  （`usage limit`、`rate limit`），但 CLI 有時回傳的是 API 的機器代碼
  （`rate_limit_error`、`resource_exhausted`）。底線寫法完全比對不到，於是
  一路掉到最後的「一般錯誤」。修法：比對前先把底線與連字號正規化成空白，
  同一組關鍵字就能同時吃到兩種寫法；另外補上 `limit exceeded`、
  `reached your limit`、`resets at`、`429 too many` 等實際會出現的講法。
- **Claude 的成功判斷太寬鬆。** 原本只看「exit code 為 0 且有輸出」就算上線，
  但 Claude CLI 超過限額時仍可能以 exit code 0 回傳，只在 JSON 裡標
  `"is_error": true`。這種情況會被誤判成**上線**（比誤判成錯誤更糟：AITeam
  會把工作派給它然後失敗）。修法：成功判斷加上檢查 `is_error` 旗標。

## 2. 管理專案：拿掉「版本升號規則」區塊

v0.14.0 Build 1 把原本的「進階設定」換成唯讀的版本升號規則說明。實際用起來
這塊只是佔位置——規則本來就寫在共用規則文件裡，放在專案設定畫面沒有實際用途，
這次整塊移除。

## 3. 管理專案：新增「專案內容」欄位

`ProjectEntry` 新增 `description` 欄位，基本資訊區塊多一個多行輸入框，讓使用者
自己寫清楚「這個專案是做什麼的」。

這個欄位不是只存著好看：`ChangeTaskService` 與 `InquiryService` 的所有 AI 提示
（Scout／Plan Gate／Implementer／查詢）都會把它接在 `Project:` 後面一起送出，
AI 因此知道它在改的是什麼東西、給誰用的，而不是只看得到一個專案名稱。沒填就
什麼都不加，行為跟以前一樣。
