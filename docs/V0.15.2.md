# AITeam v0.15.2

實測 v0.15.1 後的三項修正。

## 1. AI 狀態說明欄：灰底移除、改成一律單行

- **灰底**：說明欄用的 `AutoFitLabel` 是自訂控制項（不是一般 Label），沒有指定背景色
  時會吃到系統預設的灰色，於是在白色卡片上出現一塊灰色底。改成明確跟著卡片的白底。
- **改成單行**：原本放不下會折成兩行，實際看起來雜亂。既然放不下時本來就會自動
  降字級，就不需要折行了——改成一律單行，寬度不夠就縮字，整段文字仍然完整顯示。

## 2. GPT 已達額度上限卻顯示「上線」

v0.15.1 修的是「失敗之後怎麼分類」，但 GPT 這次是**根本沒被判定成失敗**：健康檢查
的判斷只看各家 CLI 各自的成功訊號（exit code、完成事件、`AITEAM_HEALTH_OK`），
超過限額時 CLI 仍可能正常結束並送出完成事件，於是被判成上線——接著任務一送出就
失敗（log 裡的「GPT / Codex 本次失敗，嘗試下一個 AI」）。

修法：把限額訊息的判斷抽成共用的 `LooksLikeQuota`，**三家 CLI 一律先排除**——只要
輸出或錯誤訊息裡帶有限額字樣，不管成功訊號長怎樣都不算上線，接著由既有的分類邏輯
標成「超過限額」。

## 3. Gemini 的執行結果無法閱讀

Gemini／Antigravity 的回覆是 NDJSON 串流，答案被切成很多 `text_delta` 小碎片逐一
送出。原本的解析是「收集所有字串、挑最長的一個」，永遠只拿得到殘缺片段，於是整包
原始串流 JSON 被當成答案顯示在畫面上，完全無法閱讀。

修法：新增共用的 `AntigravityStream`，把 `step_type` 為 `agent_response` 的
`text_delta` 依序接回完整答案；沒有 delta 的情況（一次回傳完整內容）才退回原本
挑最完整字串的作法。萬一兩種都解不出來，也不再把整包 JSON 丟到畫面上，改成明說
解析失敗並只保留開頭一段供診斷。

這段解析原本在 `ChangeTaskService` 與 `InquiryService` 各有一份一模一樣的複本
（同一個 bug 存在兩處），這次合併成一份共用實作。
