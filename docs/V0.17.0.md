# V0.17.0

這一版一次處理使用者實機回報的六件事。

## 1. 已登錄專案沒有出現在主畫面的下拉選單

專案管理視窗存檔後，主畫面只有在「按下『完成』且這次真的有存過東西」時才會重新載入專案清單。
用右上角的 X 關掉視窗時，`DialogResult` 是 `Cancel`，主畫面就不會重載，新增的專案自然不會出現在下拉選單裡。

- 專案管理視窗關閉後**一律**重新載入專案清單，不看 `DialogResult`。
- 下拉選單一次最多顯示 20 筆（原本是系統預設 8 筆）。

## 2. 已登錄專案改成直接拖曳排序

- 清單支援拖曳：按住卡片往上下拖，放開就換位置，拖曳過程中會畫一條線標示會插在哪裡。
- 順序直接寫回 `projects.json`，**主畫面的下拉選單跟著同一個順序**。
- 因此 `ProjectRegistryService.Load()` 不再自動照名稱排序，改用檔案裡的順序。
- 新增 `Reorder(namesInOrder)`：清單裡沒提到的專案（例如停用中的）保留在最後面，不會因為排序而消失。

## 3. 歷史任務可以刪除

- `TaskHistoryService` 新增 `Delete(id)` 與 `DeleteAll()`，索引與該筆的 log 檔一起清掉。
- 歷史任務視窗右上角新增「刪除這筆」，會先確認再刪；刪完停在同一個位置，方便連續刪除。

## 4. 「本次使用」跟狀態脫鉤

以前把「本次使用」勾掉，那一列會立刻變成「待檢查」，重新勾回來也還是「待檢查」——但用不用跟這家 AI 現在是不是上線根本是兩件事。

- `ProviderStatusRow` 改為保存最後一次真正檢查到的狀態；勾選與否只影響說明文字（顯示「本次不使用，狀態仍會持續更新」）。
- 「重新檢查」現在**三家都會檢查**，包含這一輪沒勾的，狀態隨時都是準的。
- 派工時仍然只會用「有勾 + 上線」的 AI，行為沒變。

## 5. 燈號與文字沒有水平對齊

燈號的上下邊界不對稱（上 12、下 9），TableLayoutPanel 置中時就會比旁邊的文字低一點點。改成上下都是 9，燈號才真的置中。

## 6. 參照位置改成只顯示檔名（滑過去看路徑、點一下開資料夾）

AI 回覆常把參照寫成 Markdown 連結：

```
[PROJECT_STATUS.md](file:///D:/AITeam/tasks/inquiry-6b21adf0164cefbb46621ae5fc5513/apps/CYWatermark/PROJECT_STATUS.md)
```

一份回覆裡出現十幾次，版面幾乎全被路徑占滿。

- 新增 `LogLinks.Fold()`：把 Markdown 參照折成只剩顯示文字（通常就是檔名），並記下每個檔名在文字裡的位置與它的完整路徑。
- 新增 `LinkFoldingLog`：接上唯讀的 RichTextBox，折疊後的檔名用藍色標示，**滑鼠移上去顯示完整路徑**，**點一下直接在檔案總管開啟並選取該檔**。
- 主畫面的「執行進度／結果」與歷史任務的「完整執行紀錄」都套用。
- **存進歷史紀錄的仍然是原文**（含完整路徑），折疊只發生在畫面上，資訊不會因為版面好看而遺失。
