# V0.16.2

## 這一版在解什麼問題

Claude 額度確實用完了，AITeam 的「AI 狀態」卻只顯示**錯誤**，不是**超過限額**；而且卡片上只寫「本次先跳過」，
使用者完全看不到 Claude CLI 到底回了什麼，等於沒有任何線索可以追。

根本問題有兩層：

1. **原因被丟掉**：健康檢查其實有把 CLI 原文收進 `ProviderHealth.Message`，但畫面與執行紀錄都沒有用它——
   卡片顯示的是寫死的短句，紀錄只寫狀態名稱。分類判斷萬一沒命中，訊息就永遠看不到。
   （這和 V0.16.1 在「派工失敗」那條路上修掉的是同一種毛病。）
2. **關鍵字漏接**：Claude 用完額度時的原句是
   `Session limit reached · Turn on usage credits to keep working · Resets Mon, Sep 14, 12:00 AM`，
   其中「session limit」「usage credits」原本都不在限額關鍵字清單裡。

另外補上一種以前一定會被誤報成「錯誤」的情況：CLI 改版後不認得某個參數時，健康檢查會被 CLI 直接擋下來，
跟額度、登入都無關，畫面卻一樣只顯示「錯誤」。

## 改了什麼

### 1. CLI 原文一定會出現在執行紀錄

- `ProviderHealth` 新增 `Detail`：不論分類成哪一種狀態，都帶著壓成一行、截斷到 400 字的 CLI 原文（含 exit code）。
- 主畫面檢查完每一家 AI 後，只要有 `Detail` 就多寫一行 `└ CLI 回報：…`。
- 狀態卡片的說明欄改成「本次先跳過，原因見右側紀錄」，明確指路（原文太長，塞進那一格只會被縮到看不清楚）。
- CLI 完全沒有輸出時，紀錄會寫「（CLI 沒有輸出任何訊息）」，而不是一片空白。

### 2. 限額關鍵字補上實機看到的寫法

新增 `session limit`、`weekly limit`、`usage credit`、`hit your limit`、`credits to keep working`、`resets on`。

### 3. 參數不合時自動改用精簡參數重試

- 新增 `LooksLikeUnsupportedArgument`，專門認出 `unknown option`／`unrecognized option`／`Usage:` 這類「CLI 根本沒開始跑」的失敗。
- 三家 CLI 的健康檢查都多帶一組最精簡參數；第一次因為參數被擋下來時，自動用精簡參數再問一次，
  至少能問出這家 AI 真正的狀態，而不是卡在參數問題上。兩次的原文都會留在紀錄裡。

### 4. 階段條的名稱不會再被截斷

七格階段名稱原本用 `EndEllipsis`，視窗變窄會變成「準…」。改成先自動降字級（8.5pt → 6.5pt）讓七格都放得下；
真的放不下時就只留圓點，單獨把目前階段的名稱置中寫在下方——寧可少顯示，也不顯示半個詞。

## 測試

`ProviderHealthClassifyTests` 新增：
- 實機截圖上的 Session limit 原句會被判成「超過限額」。
- 失敗時 `Detail` 會帶著 exit code 與 CLI 原文，而且壓成一行。
- `unknown option`／`Usage:` 這類失敗會被單獨認出來。
- CLI 沒有輸出時 `Summarize` 仍會給出可讀的字串。
