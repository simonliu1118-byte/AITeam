# V0.30.1

## 會議「送去執行」之後沒有真的去改

### 原因

交接視窗的「要送出的需求」預填的是**會議題目**。題目常常是問句——這次是
「鼎新 SMART ERP 的 API 要如何取得？是否有相關價格紀錄？」——修改管線前面那道
「這是查詢還是修改」的判斷看到問句，就判成查詢，回答完就結束了。

使用者按的是「送去執行」，意思已經很明確，根本不該再讓 AI 猜一次。

### 修正

- 從會議送來的任務**直接進入修改管線**，跳過查詢／修改的判斷
  （`InquiryService.RunAsync` 新增 `knownChange`）。
- 需求欄預設改成一句「去做什麼」：有定案書就拿「要做什麼」那段，沒有才退回題目。

主畫面自己打字送出的任務不受影響，照舊先判斷是查詢還是修改。

### 已知限制

專案根目錄沒有 VERSION 檔時，修改任務仍會在開工前被擋下（這次的 CYInvoice 就是）。
這是下一版要處理的「開新專案」問題的一部分。
