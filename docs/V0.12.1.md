# AITeam v0.12.1

First round of fixes from actually running v0.12.0 on Windows (the project
owner's first real hands-on test). All four are UI layout bugs, not pipeline
logic changes.

## Fixes

- **"管理專案" button text was cut off at the bottom.** Its height was locked
  to `_projectBox.PreferredHeight`, but that was read before `_projectBox`
  had inherited the window's real font (it still had WinForms' default font
  at that point), so the button was sized for a smaller font than it
  actually renders with. Fixed by setting the combo box's font explicitly
  before measuring, plus a small buffer.
- **Project Manager: the GitHub Repo dropdown's bottom edge was clipped, and
  "載入 Repo" button text didn't fit either.** Same root cause as above,
  in `_repoBox`/`_loadButton`.
- **Log line spacing was inconsistent (some lines taller than others).**
  `RichTextBox.DetectUrls` defaults to `true`, which is a known cause of
  uneven line spacing when appending plain log text. Turned it off (we
  don't need clickable links in the log) and explicitly reset
  `SelectionFont` before every append so formatting can't drift.
- **Left panel's right edge got clipped when the window wasn't maximized**
  (fine once maximized). The left/right halves were split by percentage
  with no gap between them, which left zero margin for any rounding at
  non-maximized sizes. Added a fixed 16px gutter column between them so
  there's always real breathing room regardless of window size.
- **Bonus fix while touching this code**: saving a project from the Project
  Manager was silently resetting `merge_strategy` back to `merge` every
  time, even for projects that had a different value set. It's now
  preserved like the other advanced fields.

## Not done yet

The project owner also asked for the Project Manager screen to be
redesigned (current one direction was mockup approval, not implemented in
this version) — see the "專案管理面板重新設計" artifact shared alongside this

Since this environment has no Windows runtime to actually click through the
app, these fixes are based on reading the WinForms layout code and
identifying the mechanical cause of each symptom — please confirm they look
right on the next test.
