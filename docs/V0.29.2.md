# V0.29.2

## 拿掉「設定」視窗與隱藏主控台的嘗試

V0.27.0 加了一個可開關的選項，想擋掉偶爾一閃而過的 PowerShell 黑框。**實機測試結果：無效**，
所以整個移除，回到 V0.26.0 的啟動方式。

### 測到了什麼

打勾並重開程式之後，在 Gemini 發言的過程中還是閃了。這同時確認了兩件事：

1. **那個手法擋不住。** 我們幫 CLI 準備一個隱藏的主控台讓它沿用，孫程序照樣自己開視窗。
   視窗是它開的，由它決定，上層攔不住。
2. **這不是「開程式時」才會發生的事，也不是 Codex 專屬。** 三家 AI 在 Windows 上跑工具時
   都是透過 PowerShell，所以**只要 AI 在工作中動用工具，隨時都可能閃**。
   V0.27.0 的說明把它寫成「開程式時閃一下的黑框」，範圍講窄了。

### 為什麼是整個拿掉，而不是留著改說明

留著一個已經確認沒用的勾選框，只會讓以後的人（包括我）以為那條路還有希望，再浪費一次時間。
而且打勾的狀態會讓程式用一條非預設的方式啟動 CLI——沒換到任何好處，卻多一條要維護的路徑。

真要回頭再試，V0.27.0 的說明還在，看得到當初怎麼做的。

### 移除的東西

- `HiddenConsole`（`AllocConsole` + `SW_HIDE` + `SetConsoleCtrlHandler`）
- `SettingsForm` 與主畫面右上角的「設定」按鈕
- `ProcessRunner.InheritHiddenConsole` 與 `CreateStartInfo` 的 `inheritHiddenConsole` 參數，
  `CreateNoWindow` 回到固定 `true`
- 偏好裡的 `hide_cli_console`

`AppPreferencesService` 留著——「上次由誰整理定案書」還在用它。舊的 `preferences.json` 裡
留下來的 `hide_cli_console` 會被忽略，不影響讀取。

### 這個閃窗怎麼辦

目前接受它。它不影響任何功能，純粹是視覺上的干擾。Windows 沒有讓上層程式管孫程序怎麼開
視窗的乾淨辦法，硬試只會把啟動流程弄得更複雜、更容易壞，卻還是擋不住。
