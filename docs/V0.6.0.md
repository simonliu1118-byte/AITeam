# AITeam v0.6.0

Structural release. No user-visible behavior change; this release makes the codebase testable and adds the first automated regression tests.

## Changes

- Extracted all non-UI logic (`Models`, `ProcessRunner`, `InquiryService`, `ChangeTaskService`, `GitRepositoryService`, `ProviderHealthService`, runtime/project-registry services) out of `src/AITeam.App` into a new `src/AITeam.Core` class library targeting plain `net8.0` (no WinForms dependency). `AITeam.App` now only contains the WinForms UI (`MainWindow`, `ProjectManagerForm`, `ProviderStatusCard`, `RoundedCard`, `Program`) and references `AITeam.Core`.
- Introduced `IProcessRunner` (implemented by `ProcessRunner`) so process execution can be faked in tests. `InquiryService`, `ChangeTaskService`, `GitRepositoryService`, and `ProviderHealthService` now depend on the interface instead of the concrete class; no caller changes were needed since `ProcessRunner` still implements it.
- Made the pure decision-logic methods that most needed regression coverage `internal` (`ChangeTaskService.ParseRisk` / `ParseVersionBump` / `ReviewPassed`, `InquiryService.Parse`, `GitRepositoryService.GetRemoteDefaultBranchAsync` / `NormalizeGitHubRepo` / `RemoteMatches`), exposed to a new test assembly via `InternalsVisibleTo`.
- Added `tests/AITeam.Core.Tests` (xUnit), the first automated test suite in this repository. It covers: risk/version-bump/review-pass parsing, inquiry-vs-change intent classification, GitHub repo URL normalization/matching, and — most importantly — the exact default-branch selection precedence (`origin/HEAD` → registered `DefaultBranch` → guessed `main`/`master`) that a previous release got wrong before it was fixed in v0.5.1.
- CI (`build-windows.yml`) now runs a `test` job on `ubuntu-latest` (`dotnet test`) before the Windows self-contained publish job; the Windows job now depends on the tests passing (`needs: test`).

## Why

This is the structural foundation the v0.5.1 patch highlighted the need for: v0.5.0 shipped with the change-task pipeline always reporting the wrong `RequestIntent`, and nothing caught it because there were no tests. This release does not change product behavior — it makes the next such bug much more likely to be caught before release.

## Still next

- Wire up `config-templates/settings.json` / `agents.json` so `max_repair_rounds` and CLI paths are actually configurable instead of hard-coded.
- Add a worktree/task cleanup tool for failed/kept-for-inspection artifacts.
- Harden the Antigravity stream-json answer extraction against prompt-echo false positives, backed by a captured real transcript fixture.
- Add a HIGH risk manual-confirmation gate before `ChangeTaskService` pushes a formalized change (mirrors the low/normal-auto, high-manual policy now used for AITeam's own release PRs).
