# AITeam v0.8.0

Second implemented step of `docs/PIPELINE_REDESIGN.md` (§4.1, §4.2): degraded
2-AI review handling and Challenger/Final Reviewer role rotation.

## Changes

- **Degraded review, made visible instead of silently allowed.** When only 2 of
  the 3 AIs are online, `ChangeTaskService` used to pick Challenger and Final
  Reviewer independently from the implementer, which — because of how the
  preference lists happened to resolve — always collapsed both roles onto the
  same single AI without anyone noticing. It now explicitly detects this case
  (`TryPickDifferentFromAny`, tried against both the implementer *and* the
  Challenger before falling back), and when it does happen:
  - logs a clear `⚠️ 僅 2 個 AI 上線…獨立性下降` warning both when roles are
    assigned and on every round
  - tells the Final Reviewer prompt it already wrote the Challenge this round
    and to actively second-guess itself rather than rubber-stamp
  - carries a `DegradedReview` flag on `ChangeTaskResult`, included in the
    final completion summary so it's visible even after the log has scrolled
- **Role rotation when all 3 AIs are online.** Previously the same
  Challenger/Final-Reviewer pair was reused for every repair round. Starting
  from repair round 2, the two non-implementer AIs now swap identities each
  round, so a "second opinion" really is a different perspective instead of
  the same reviewer re-reading its own earlier verdict. `ChangeTaskResult`'s
  `FinalReviewer` now reports whoever actually cast the deciding vote, not the
  role assignment made before the loop started.
- Added `tests/AITeam.Core.Tests`: `ChangeTaskServiceRoleSelectionTests`
  covering the degraded-detection logic (all three 2-online combinations) and
  the "third provider found when all three are online" / preference-order
  cases.

## Not yet in this release

The "effective risk escalates one tier under degraded review" idea from
`PIPELINE_REDESIGN.md` §4.1 has no effect yet — it only matters once the
risk-gated merge decision (§5, `PIPELINE_REDESIGN.md`'s version 6) exists.
Implementing it now would be dead code with nothing to consume it; it will
land together with that version instead.

See `docs/PIPELINE_REDESIGN.md` for the full plan and remaining items.
