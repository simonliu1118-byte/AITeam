# V0.17.1

## 讓 AI 讀得到 GitHub 上的三層規則（只指路，不貼全文）

### 問題

三層規則（`REPOSITORY_RULES.md` → `REPO_POLICY.md` → `PROJECT_RULES.md`）已經同步在每個納管 repo 的根目錄，
AITeam 派工時也會把 repo 同步到本機，**規則檔其實一直都在 AI 的工作副本裡**——但 AITeam 送出的 prompt
從來沒有提過它們，所以 AI 不會主動去讀。

### 為什麼不把規則全文貼進 prompt

三份規則加起來約 26 KB，換算約 8,000～10,000 tokens。每個任務、每個 AI、每一輪都貼一次，
成本非常高，而且大部分內容跟當次工作無關。

改成只放一句指路，約 30 tokens，差距約 300 倍。AI 需要時自己開檔，而同一個工作階段內讀過的檔
會留在它自己的上下文裡，不會重複讀。

### 改了什麼

`ChangeTaskService.DescribeProject()` 是 Scout、Plan Gate、Implement 與 Inquiry 四個 prompt 共用的
專案說明區塊，在它後面固定加上一段 `RulesPointer`：

- 指出規則入口在 repo 根目錄的 `AGENTS.md`，以及它索引的三層規則檔
- 要求從本機工作副本讀取並遵守
- 明確說明「使用者當次的明確指示優先於規則沒涵蓋的部分」
- **找不到 `AGENTS.md` 就跳過**，不要反過來要使用者貼規則

因為是加在共用區塊，四個 prompt 一次到位，不需要逐一改。

### 沒有做的部分

在每個納管 repo 放 `CLAUDE.md` / `GEMINI.md`（讓 Claude 與 Gemini 也能像 Codex 讀 `AGENTS.md` 一樣
自動載入規則入口）**沒有做**——`RULES_INDEX.md` 明文禁止平行規則入口，要做必須先走 `governance/*`
branch 修改白名單，屬於規則變更，不在本次範圍。
